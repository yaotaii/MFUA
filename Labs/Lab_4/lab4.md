# Контрольные вопросы 

## Что такое командная строка?

Командная строка в контексте вычислительных сетей и телекоммуникаций представляет собой текстовый интерфейс управления, который полностью исключает графические элементы и окна. Пользователь или сетевой администратор взаимодействует с операционной системой или активным сетевым оборудователем, например маршрутизатором или коммутатором, путём ввода специальных текстовых строк, которые называются командами. Система после получения такой строки интерпретирует её, выполняет встроенную программу или изменяет настройки сети и затем выводит результат тоже в виде текста, после чего снова переходит в состояние ожидания следующей команды. Это циклическое приглашение к вводу и есть работа командной строки.

В телекоммуникациях этот инструмент имеет критическое значение, потому что серверы, промышленные маршрутизаторы и управляемые коммутаторы часто вообще не имеют графического интерфейса, а подключение к ним осуществляется удалённо по протоколам SSH или Telnet, которые передают только текст. Именно через командную строку специалист назначает интерфейсам сетевые адреса, прописывает статические маршруты, настраирует списки доступа или проверяет состояние каналов связи с помощью утилит вроде ping для измерения задержек и потерь пакетов или traceroute для отслеживания пути сигнала через узлы сети. Даже на обычном домашнем компьютере через командную строку можно выполнить диагностику: например, сбросить кэш DNS, посмотреть таблицу активных соединений netstat или вручную обновить аренду IP-адреса у DHCP-сервера.

Основная сложность работы с командной строкой заключается в том, что она требует точного знания синтаксиса и запоминания большого количества команд и их параметров, а при ошибке ввода система не выполнит действие и выдаст сообщение об ошибке, которое тоже придётся интерпретировать. Тем не менее, для специалиста по сетям она остаётся незаменимой, поскольку позволяет автоматизировать рутинные действия через написание скриптов, работать с очень низким потреблением ресурсов и получать доступ к детальным настройкам, которые часто скрыты за упрощёнными графическими оболочками. Таким образом, командная строка — это не просто вспомогательный инструмент, а основной рабочий язык общения с сетевым оборудованием.

## Перечислите основные команды управления файлами в командной строке;

В командной строке операционных систем семейства Windows и Linux набор команд для управления файлами различается, но логически они очень похожи. Ниже перечислены основные команды, актуальные для типичной командной оболочки (в скобках указаны различия там, где это принципиально).

Команда для просмотра содержимого каталога — dir в Windows или ls в Linux. При её вводе система выводит на экран список всех файлов и папок, находящихся в текущем рабочем каталоге, включая их атрибуты, размер и дату изменения. В Windows эта команда традиционно используется для навигации, а в Linux её применяют с дополнительными ключами, например ls -la для показа скрытых файлов и подробных прав доступа.

Команда для смены текущего каталога — cd (сокращение от change directory) работает одинаково почти во всех системах. Чтобы перейти в папку «Документы», нужно написать cd Documents, а для возврата на один уровень вверх — cd ... В Windows для перехода на другой диск требуется сначала указать букву диска с двоеточием, например D:, и только потом использовать cd, тогда как в Linux все диски смонтированы в единую файловую иерархию, начинаясь от корня /.

Команда для создания нового каталога — mkdir (make directory) позволяет создать одну или несколько новых папок в любом месте файловой системы, если у пользователя есть на это права записи. Например, команда mkdir new_folder создаст подпапку внутри текущего каталога.

Команда для удаления файлов — del в Windows или rm в Linux. В Windows del file.txt удалит указанный файл, но не сможет удалить папку, для чего используется отдельная команда rmdir. В Linux команда rm более универсальна и опасна: rm file.txt удаляет файл, а rm -r folder рекурсивно удаляет папку со всем её содержимым без возможности простого восстановления. Ключ -f в Linux заставляет удалять файлы даже с защитой от записи без запроса подтверждения.

Команда для копирования файлов — copy в Windows и cp в Linux. Синтаксис в обоих случаях требует указать источник и назначение: copy source.txt destination.txt создаст точную копию файла с новым именем, а copy file.txt C:\backup\ скопирует файл в другую папку, сохранив исходное имя. В Linux команда cp с ключом -r может копировать целые директории рекурсивно.

Команда для перемещения или переименования файлов — move в Windows и mv в Linux. Это одна и та же операция с точки зрения файловой системы: когда вы перемещаете файл в другую папку, вы изменяете его путь, а когда переименовываете, вы меняете только имя внутри того же каталога. Например, move oldname.txt newname.txt переименует файл, а move file.txt ..\Папка\ переместит его на уровень выше в указанную папку.

Команда для просмотра содержимого текстового файла — type в Windows и cat в Linux. При вводе type readme.txt командная строка сразу же выведет всё содержимое этого текстового файла на экран. Для очень больших файлов в Linux удобнее использовать less или head, которые показывают информацию постранично или только первые строки.

Команда для удаления каталога — rmdir в Windows и rmdir или rm -r в Linux. В Windows команда rmdir folder удалит только пустую папку; для удаления папки с файлами нужно использовать ключ /s. В Linux стандартный rmdir тоже работает только с пустыми каталогами, поэтому для удаления папки со всем содержимым обычно используют rm -r folder, что делает эту операцию необратимой без специальных средств восстановления.

Важно помнить, что в классической командной строке, в отличие от графического интерфейса, удалённые файлы обычно не попадают в корзину и восстанавливаются с большим трудом, поэтому команды вроде rm -rf в Linux считаются потенциально опасными и требуют особой осторожности при наборе.

## Перечислите команды вывода основной информации системы;
Команда для просмотра информации об операционной системе — в Windows это команда systeminfo, которая выдаёт развёрнутый отчёт: версию ОС, дату установки, производителя, загрузочную папку, объём физической и виртуальной памяти, а также список установленных обновлений (hotfixes). В Linux аналогом является команда uname -a, которая показывает имя ядра, версию, архитектуру процессора и дату компиляции ядра, а для получения сведений о дистрибутиве используется команда cat /etc/os-release или lsb_release -a.

Команда для просмотра информации о процессоре — в Windows используется команда wmic cpu get name, numberofcores, maxclockspeed, которая выводит название модели процессора, количество ядер и максимальную тактовую частоту. Также можно выполнить команду dxdiag (Diagnostics Tool), которая запускает графическое приложение DirectX, но через командную строку можно вызвать её с ключом /dontskip для вывода информации в текстовом виде. В Linux команда lscpu показывает полную архитектуру процессора, включая количество потоков, кэши всех уровней, поддерживаемые виртуализации и текущую частоту работы ядер, а более компактный вариант — cat /proc/cpuinfo | grep "model name" | uniq.

Команда для просмотра информации об оперативной памяти — в Windows команда systeminfo | findstr "Memory" отфильтрует строки с объёмом доступной и виртуальной памяти, а отдельная команда wmic memorychip get capacity, speed покажет ёмкость и скорость работы каждого физического модуля памяти. В Linux стандартная команда free -h выводит очень наглядную таблицу с общим объёмом, использованной, свободной и буферной памятью в удобном для человека формате (гигабайты или мегабайты), а для получения детальной информации о каждом слоте памяти используется sudo dmidecode --type memory.

Команда для просмотра информации о дисках и разделах — в Windows команда wmic logicaldisk get size, freespace, caption перечисляет все логические диски с буквами (C:, D:), их полный размер и свободное место. Для более детальной информации о физических разделах используется diskpart с последующим вводом list disk внутри этой утилиты, либо команда wmic diskdrive get model, size. В Linux команда df -h показывает занятое и свободное место на всех смонтированных файловых системах, а lsblk выдаёт древовидную структуру всех дисков и разделов, включая их типы, метки и точки монтирования.

Команда для просмотра сетевой конфигурации — в Windows используется ipconfig /all, которая выдаёт исчерпывающую информацию о каждом сетевом адаптере: физический MAC-адрес, IP-адрес, маску подсети, шлюз по умолчанию, адреса DNS-серверов и статус DHCP. В Linux современной альтернативой устаревшему ifconfig является команда ip addr show, которая показывает все сетевые интерфейсы, их IP-адреса и состояние, а для просмотра маршрутизации используется ip route show, а для информации о DNS-серверах — cat /etc/resolv.conf.

Команда для просмотра списка запущенных процессов — в Windows команда tasklist выводит таблицу всех выполняющихся в данный момент приложений и системных служб с их идентификаторами PID, объёмом используемой памяти и именем исполняемого файла. Для остановки процесса используется taskkill /PID номер. В Linux аналогом является команда ps aux, которая показывает все процессы всех пользователей в детальном формате, включая процент загрузки процессора и памяти, а для динамического обновления в реальном времени используется команда top или её улучшенная версия htop.

Команда для просмотра системных логов и событий — в Windows командная строка может читать журнал событий через wevtutil qe System /c:10 /f:text, которая выведет последние десять записей системного журнала в текстовом формате. Более простой вариант — eventvwr открывает графическую оснастку, но из командной строки можно использовать systeminfo для поиска критических событий. В Linux система логирования традиционно основана на файлах в каталоге /var/log/, и основная команда для просмотра системного журнала — journalctl, особенно в системах с systemd; например, journalctl -xe покажет последние сообщения об ошибках, а dmesg выводит кольцевой буфер ядра, полезный для диагностики оборудования.

Универсальная команда для сводной информации — в Linux существует пакет neofetch или screenfetch, которые не входят в стандартную поставку, но при установке выводят красочное ASCII-изображение логотипа дистрибутива и рядом все ключевые параметры системы: версию ОС, ядро, среду рабочего стола, тему оформления, процессор, видеокарту и использование памяти. В Windows частичным аналогом можно считать команду msinfo32, которая запускает приложение "Сведения о системе", но из самой командной строки без открытия окна информацию извлечь сложнее, поэтому чаще пользуются комбинацией перечисленных выше команд systeminfo, wmic и ipconfig.

## Перечислите команды ввода/вывода файлов

Ввод и вывод файлов в командной строке понимается двояко: с одной стороны, это команды для чтения содержимого файлов (вывод на экран), с другой — команды для перенаправления потока данных из одного места в другое (ввод из файла или запись вывода в файл). Ниже перечислены основные команды и операторы.

Команда для вывода содержимого файла на экран — type в Windows и cat в Linux. Например, type readme.txt покажет всё, что записано внутри этого текстового файла. В Linux также широко используется less для постраничного просмотра больших файлов и head или tail для вывода только начала или конца файла.

Команда для копирования содержимого файла в другой файл — copy в Windows и cp в Linux. Это одновременно и управление файлами, и операция вывода: исходный файл читается (ввод), а его содержимое записывается в новый файл (вывод). Например, copy a.txt b.txt сделает полную копию.

Операторы перенаправления вывода — символ > и >> работают одинаково в Windows и Linux. Если написать command > file.txt, стандартный вывод команды, который обычно идёт на экран, будет перенаправлён в указанный файл, причём если файл существовал, его содержимое будет полностью заменено новым. Двойной символ >> делает то же самое, но не заменяет файл, а добавляет новые строки в его конец. Например, dir > list.txt сохранит список файлов текущего каталога в текстовый документ, а echo "Новая строка" >> log.txt допишет эту строку в конец файла журнала.

Операторы перенаправления ввода — символ < используется для того, чтобы команда читала данные не с клавиатуры, а из заранее подготовленного текстового файла. Например, команда sort < data.txt возьмёт содержимое файла data.txt, отсортирует его и выведет результат на экран, при этом сама команда sort даже не узнает, что данные пришли из файла, а не от пользователя.

Конвейеры (пайпы) — символ | соединяет вывод одной команды со вводом другой. Это мощнейший механизм, позволяющий строить сложные цепочки обработки данных без создания промежуточных файлов. Например, cat log.txt | find "ошибка" | sort сначала прочитает файл с журналом, потом отфильтрует строки, содержащие слово «ошибка», а затем отсортирует их все в одной строке команды.

Команда для чтения ввода с клавиатуры в скриптах — в Windows это set /p var=Введите значение:, в Linux — read var. Эти команды не используются напрямую в ручном режиме, но очень важны для сценариев: они приостанавливают выполнение скрипта, ждут, пока пользователь что-то напечатает и нажмёт Enter, а затем сохраняют введённую строку в переменную, которую можно использовать дальше.

Команда для вывода текста напрямую — echo существует во всех системах. echo Hello просто напечатает слово Hello на экране, а echo Hello > greeting.txt запишет его в файл, что делает echo основной командой для создания коротких текстовых файлов из командной строки.

## Возможно ли полноценное управление системой, пользуясь только командной строкой? Ответ обоснуйте.

Да, полноценное управление современной вычислительной системой, пользуясь только командной строкой, не просто возможно, а во многих случаях является основным или даже единственным способом такого управления, особенно в профессиональной среде. Это утверждение справедливо для серверных версий операционных систем, для встраиваемых систем и для сетевого оборудования, где графический интерфейс либо отсутствует в принципе, либо работает как необязательная надстройка над текстовой консолью.

Обосновать это можно на нескольких уровнях. Во-первых, все фундаментальные административные задачи имеют текстовые реализации. Управление пользователями и правами доступа выполняется командами вроде net user или useradd, настройка сети — ipconfig или ip, управление службами — sc в Windows и systemctl в Linux, управление дисками — diskpart или fdisk, мониторинг ресурсов — tasklist и top. Ни одна из этих операций не требует графического интерфейса: если знать правильную команду и её ключи, можно сделать ровно то же самое, что и в диалоговых окнах, а часто и больше — например, через командную строку доступны параметры, которые в графической утилите просто не выставлены.

Во-вторых, командная строка позволяет выполнять операции, которые в графическом режиме вообще невозможны или чрезвычайно затруднены. Это пакетная обработка тысяч файлов по сложным условиям, автоматическая настройка системы с помощью скриптов, удалённое управление через SSH без необходимости физического присутствия у монитора компьютера. Администратор дата-центра, обслуживающий сотни серверов, физически не может иметь графический доступ к каждому — он подключается по сети к командной строке, пишет скрипт и запускает его сразу на всех машинах.

В-третьих, даже в ситуациях, когда графический интерфейс разрушен или не загружается, командная строка часто остаётся единственным каналом спасения. Когда Windows не загружается до рабочего стола, консоль восстановления или безопасный режим с поддержкой командной строки позволяют исправить конфигурационные файлы, восстановить загрузчик, скопировать повреждённые драйверы. В Linux графический сервер (X11 или Wayland) может полностью отказывать, но многопользовательский текстовый режим запускается всегда, если ядро и базовая система целы.

Наконец, важно понимать, что многие графические утилиты сами являются лишь обёртками вокруг командной строки. Когда вы меняете IP-адрес в окне настроек Windows, система в конечном счёте вызывает те же самые функции, которые доступны через netsh interface ip set address. Аналогично, утилита gparted для управления разделами диска в графическом виде всего лишь предоставляет удобный интерфейс к консольным командам fdisk, mkfs и mount. Профессиональные администраторы часто предпочитают командную строку именно потому, что она даёт полный контроль, прозрачность действий и возможность задокументировать каждый шаг в виде скрипта, тогда как серия кликов мышью не оставляет следа и её трудно воспроизвести в точности.

Ограничения у командной строки, конечно, есть: просмотр изображений, воспроизведение видео, работа с графическими документами вроде таблиц со сложным форматированием возможны лишь через специальные консольные просмотрщики, которые всё равно будут выводить грубую текстовую или псевдографическую версию. Но для собственно управления системой — настройки, диагностики, автоматизации, мониторинга — командная строка не только достаточна, но и во многих сценариях превосходит графические альтернативы по скорости, гибкости и надёжности.

##  Подумайте, чем отличается командная строка Windows от командной строки MS-DOS, несмотря на их схожесть в командах.

На первый взгляд интерфейс командной строки в современных версиях Windows и в старом дисковом операционном окружении MS-DOS выглядит почти одинаково: чёрное окно с мигающим курсором после приглашения типа C:\> и ожидание ввода знакомых команд dir, copy, del, cd. Однако внутреннее устройство и реальные возможности этих двух сред кардинально различаются, потому что они работают на совершенно разных уровнях операционной системы.

Главное и принципиальное отличие заключается в том, что MS-DOS была полноценной операционной системой, которая управляла компьютером напрямую. Когда вы вводили команду в DOS, она работала с аппаратным обеспечением через BIOS или напрямую обращалась к портам ввода-вывода, управляла прерываниями и имела прямой доступ ко всей оперативной памяти и диску. Современная же командная строка Windows — это всего лишь одно из прикладных окон, которое запускается внутри уже работающей операционной системы Windows, которая в это время продолжает управлять памятью, процессами, драйверами и безопасностью. Командная строка Windows работает в так называемом защищённом режиме, и многие из команд, которые в DOS выполняли низкоуровневые действия, в Windows либо эмулируются, либо вообще недоступны напрямую.

Отсюда вытекает второе важнейшее различие: доступ к аппаратному обеспечению. В MS-DOS команда могла напрямую записать данные в любой сектор диска в обход файловой системы, изменить вектор прерывания клавиатуры или вывести графическое изображение путём прямой записи в видеопамять. В командной строке Windows такие операции запрещены на уровне архитектуры системы: любое обращение к диску, памяти или устройствам проходит через драйверы и проверки безопасности, и попытка выполнить команду, аналогичную старым низкоуровневым утилитам DOS, приведёт к сообщению об ошибке или потребует прав администратора, но и с правами администратора это будет уже обращение через специальные API, а не прямое управление портами.

Третье существенное отличие касается многозадачности и многопоточности. MS-DOS была однозадачной системой: пока одна команда выполнялась, командная строка ждала её завершения, и ничего другого в это время на компьютере происходить не могло, если только не использовались специальные программы-резиденты. Командная строка Windows работает в среде с вытесняющей многозадачностью: вы можете запустить команду, она будет выполняться в отдельном процессе, и в это же время через другое окно или даже из той же самой командной строки (запустив команду с амперсандом или с помощью start) можно запустить другую программу, и они будут работать одновременно под управлением планировщика Windows.

Кроме того, командная строка Windows поддерживает длинные имена файлов и пробелы в них, тогда как MS-DOS работала только с форматом 8.3 — не более восьми символов в имени и трёх в расширении. При попытке в современной командной строке перейти в папку «Мои документы» вы просто пишете cd "Мои документы", тогда как в DOS пришлось бы использовать сокращение «MYDOCU~1». Точно так же современная командная строка поддерживает Юникод, то есть вывод на экран русских букв и тысяч других символов, тогда как MS-DOS работала лишь с ограниченной кодовой страницей 866 или 437.

Наконец, важное различие заключается в том, что командная строка Windows является лишь интерфейсом к другому интерпретатору, который в современных версиях Windows называется PowerShell, а также к среде выполнения Win32. Старые команды вроде dir или copy не являются самостоятельными программами в полном смысле слова, а встроены в интерпретатор CMD.EXE. В MS-DOS все команды были либо встроены в COMMAND.COM, либо представляли собой отдельные файлы с расширением COM, EXE или BAT, которые выполнялись поверх микроскопического ядра. Можно сказать, что MS-DOS был сплошной командной строкой из одного слоя, а в Windows командная строка — это одна из многих программ, живущая внутри огромной сложной системы и жёстко ограниченная её защитными механизмами. Но именно благодаря этим ограничениям и более глубокой интеграции современная командная строка Windows может делать вещи, которые MS-DOS не снились, например запускать команды на удалённых компьютерах по сети, управлять службами Windows или работать с объектами WMI, чего в эпоху DOS просто не существовало.

## Приведите примеры интерпретаторов команд в других операционных системах.

Интерпретаторы команд существуют практически во всех операционных системах, и у каждой системы есть свой стандартный инструмент, а часто и несколько альтернативных на выбор. Вот основные примеры.

Bash (Bourne Again SHell) — это самый распространённый интерпретатор в мире Linux и большинства дистрибутивов, а также в macOS до недавнего времени. Он поддерживает историю команд, автодополнение по клавише Tab, мощные сценарии с циклами, условиями и функциями, а также такие удобства, как псевдонимы (alias) для сокращения частых команд.

Zsh (Z Shell) — современная и очень популярная альтернатива Bash, которая стала стандартной командной оболочкой в macOS начиная с версии Catalina. Zsh славится улучшенным автодополнением с подсказками, более гибкой настройкой приглашения командной строки, проверкой правописания команд и множеством готовых тем оформления через фреймворк Oh My Zsh.

Fish (Friendly Interactive SHell) — интерпретатор, который сделан для удобства работы человека интерактивно. Он выделяет синтаксис цветом прямо при наборе, подсказывает возможные команды и аргументы по мере ввода, причём подсказки автоматически обучаются на основе истории. Fish не полностью совместим со стандартом POSIX, то есть некоторые скрипты, написанные для Bash, в нём могут не работать, зато работа с ним вручную гораздо приятнее, чем с большинством других оболочек.

Командная строка macOS (терминал) — до перехода на Zsh в macOS по умолчанию использовался Bash, но сама графическая оболочка представляет собой терминальное приложение, внутри которого может работать любой установленный интерпретатор. Кроме того, в macOS сохранилась старая оболочка от NeXTSTEP (предка macOS), которая называется tcsh, хотя сейчас используется редко.

PowerShell — это не просто командная строка, а мощный объектно-ориентированный интерпретатор от Microsoft, доступный не только в Windows, но и в Linux и macOS. В отличие от классических текстовых оболочек, где команды обмениваются строками, PowerShell передаёт между командами целые объекты .NET со свойствами и методами, что позволяет выполнять очень сложную обработку данных без избыточного парсинга текста. PowerShell — полноценный язык сценариев, который может управлять COM-объектами, реестром Windows, сертификатами и многим другим.

Командная строка FreeBSD и других BSD-систем — по умолчанию в этих системах используется оболочка tcsh, которая является улучшенной версией старой C Shell (csh). Tcsh добавляет к оригинальной C Shell редактирование командной строки, историю, дополнение имён файлов и команд, причём синтаксис сценариев похож на язык программирования C, отсюда и название.

Командная строка Android (ADB shell) — в операционной системе для мобильных устройств под капотом находится ядро Linux, поэтому при подключении через ADB (Android Debug Bridge) или в терминальном приложении на самом устройстве пользователь попадает в оболочку, которая обычно является упрощённым вариантом Bash или заменой под названием mksh (MirBSD Korn Shell). Доступ к командам ограничен из-за модели безопасности Android, но многие стандартные утилиты вроде ls, cat и ps работают.

Командная строка Cisco IOS — сетевое оборудование Cisco использует собственную командную оболочку, которая называется CLI (Command Line Interface). У неё есть иерархические режимы: пользовательский режим с ограниченными командами, привилегированный режим для просмотра конфигурации и глобальный режим настройки. Команды не являются полноценными сценариями, но позволяют сохранять и выполнять небольшие последовательности. В коммутаторах и маршрутизаторах других производителей (Juniper, Arista, Huawei) также есть свои интерпретаторы, часто с очень похожим синтаксисом, заимствованным у Cisco.

Оболочка управляющей программы IBM z/OS — в мейнфреймах IBM существует командная оболочка под названием TSO/E (Time Sharing Option/Extensions) и её диалоговый вариант ISPF, которые позволяют управлять файлами в системах с иерархией каталогов, отличной от UNIX, запускать пакетные задания JCL и взаимодействовать с транзакционными мониторами CICS.

Оболочка Symbian OS — в старой смартфонной операционной системе Symbian существовал интерпретатор команд под названием *NORTi*, который был доступен через так называемый экран отладки и мог выполнять базовые файловые операции, управлять процессами и выгружать системную информацию, хотя обычному пользователю он был недоступен.

BusyBox — это не отдельный интерпретатор, а программный пакет, который объединяет несколько десятков команд в один исполняемый файл и часто используется во встраиваемых системах, маршрутизаторах фирмы Linksys, в многих прошивках для роутеров (OpenWrt, DD-WRT), а также в контейнерах Docker для минимизации размера образа. BusyBox запускает свою встроенную оболочку (обычно ash, упрощённую версию Bourne Shell), которая понимает все стандартные команды, но каждая из них реализована минимально и без многих редко используемых опций.
